# 用户词库覆盖层格式

## 文件与字段

用户词库是独立于 `production.lex` 和 `user-model` 的 UTF-8 文本文件。首行可带 UTF-8 BOM，输入支持 LF、CRLF、空文件和末行无换行；规范化保存使用 UTF-8、LF、无 BOM。

每个非空数据行必须恰好包含一个 TAB：

```text
词条<TAB>编码
词条<TAB>编码#删
词条<TAB>编码#固
词条<TAB>编码#N
```

编码沿用第一阶段的严格规则：1～64 个小写 ASCII 字母。词条沿用文本码表的常用 CJK、最多 32 字符规则。空格不能代替 TAB，多余字段、空字段、未知标记、多个标记、标记位于中间、非法 UTF-8 和非法编码都会被拒绝；诊断包含路径、物理行号、字段和原因，但不回显整行私人内容。

### 全拼方案命名空间

阶段 2 为 `quanpin` 使用 `qp` 代码前缀，前缀属于持久化编码但不会显示为候选读音：

```text
自定义词<TAB>qpzidingyici
全拼固顶词<TAB>qpquanpingudingci#固
```

因此旧小鹤双拼规则 `ni` 只作用于 `xiaohe`，全拼规则 `qpni` 只作用于 `quanpin`。显式分音符不写入人工编码；`xi'an` 的人工规则写作 `qpxian`。该约定保持现有两字段格式和原子保存合同不变，并为后续方案保留独立命名空间。

## 四种规则

- 无标记：增加普通用户候选；同码的系统候选全部排在它之前。
- `#删`：只隐藏完全相同的“当前编码＋词条”，不修改系统二进制词库，也不影响其他编码下的同名词。
- `#固`：固定在同码最终候选的最前方；多个固顶按最终有效规则的 `source_order` 排列。
- `#N`：放在最终同码列表从 1 开始的第 N 位；位置类型为 `u16`，合法范围为 1～65535。`#0`、负数、正号、小数、空数字和溢出均非法。

同一文件内重复出现相同“编码＋词条”时，后出现的有效规则覆盖先前规则，并保留后一条的 `source_order`。快照按最终有效记录的源顺序保存，不依赖哈希遍历顺序。

## 硬排序

系统基础频率、整句评分和 `user-model` 学习先完成软排序，再按以下顺序应用人工规则：

1. `#删` 过滤精确的编码＋词条；
2. 保留系统候选的软排序，并将普通用户候选追加到全部同码系统候选之后；重复文本由用户来源替代系统来源并按普通用户候选处理；
3. 建立 `#固` 保护前缀；
4. 放置 `#N`；
5. 稳定去重；
6. 最后执行数量限制与候选会话分页。

多个规则请求同一有效位置时按 `source_order` 连续放置。超出列表长度的位置稳定追加。`#固` 优先于 `#N`：

```text
effective_position = max(N, fixed_count + 1)
```

因此任何 `#N` 都不能插入固顶前缀。位置是完整候选列表中的全局位置，不是当前页位置。

精确/前缀路径保持“精确优先、没有精确规则才使用更长编码前缀”。空输入不枚举整个用户词库。生产小鹤双拼仍先使用既有 `ExistingRanking`，用户规则只覆盖当前 raw code，不把系统候选切换为码表顺序。

## 独立码表运行时接入

阶段 11.6.4 复用同一解析器、规则模型和不可变快照，不新增文件格式或码表专用解析器。系统码表先按分类顺序与分类内 `source_order` 形成完整候选，再应用本文件的硬排序，最后才限量和分页。

正式 `xiaohe-yinxing` 的规则源固定为两层：冻结包内 `user-rules.txt` 先进入基础快照，外部 `userLexiconPath` 后进入覆盖快照。合并键是“完整编码＋词条”，后层覆盖前层，新的稳定 `source_order` 按内置有效规则后接外部有效规则重建。缺失、空或双损坏外部文件等价于空外层，不能移除内置规则；外部有效备份恢复后仍覆盖内置同键规则。`code-table-fixture` 不含包内层，保持原有外部快照语义。

码表候选保留自己的完整编码。`#删` 只删除完全相同的“候选完整编码＋词条”，因此前缀查询时不会误删其他更长编码下的同名词；如果当前精确系统候选被删空，也不会在同一次查询中重新混入更长系统前缀。普通、固顶和位置规则仍按既有 exact-or-prefix 快照选择语义参与当前查询，后规则覆盖不变。

引擎创建时完整解析一次用户文件，并用 `Arc<UserLexiconSnapshot>` 在只读查询间共享。reset、候选会话重建、清空 `user-model` 和方案切换只清组合状态，不清用户规则；新句柄或新进程从同一路径重新加载。管理页面保存后可显式热重载，完整加载成功才原子替换快照；主文件损坏时优先恢复备份，运行中双损坏保留最后有效快照且系统码表仍可查询。

## 保存、备份与恢复

正式管理接口为文档级 compare-and-swap：读取返回规范化内容对应的稳定 `revision`；保存必须携带该 revision。若磁盘已经被其他窗口或进程更新，返回 `revision_conflict`，不进入替换流程。空文件和不存在文件也有稳定 revision，因此首次创建与清空使用同一合同。

主文件的同目录辅助文件为：

```text
user_lexicon.txt
user_lexicon.txt.tmp
user_lexicon.txt.bak
user_lexicon.txt.old
```

保存先完整写入 `.tmp`，执行 `flush` 和 `sync_all`，重新解析校验后才切换。已有主文件先形成并同步备份，再移到可回滚的 `.old`，最后把 `.tmp` 改名为主文件；任何失败都会清理临时文件并尽量恢复旧主文件。Windows 和 HarmonyOS/Linux 均不采用“先删除主文件再逐行写入”。同一快照重复保存产生相同规范化字节。

加载行为：

- 主文件有效：加载主文件；
- 主文件和备份都不存在：空覆盖层；
- 主文件损坏、备份有效：加载备份并返回 `LoadedBackup` 与脱敏警告码；
- 主文件与备份都损坏：初次加载使用空覆盖层，系统候选仍可用；
- 已有运行时快照的 reload 失败：保留最后一个有效快照。

运行时只使用完整解析后生成的不可变快照，不在按键热路径读盘或解析文本。Release 日志不得输出完整词条、整行内容或整个用户词库。

## 当前阶段边界

阶段 12 已提供正式用户词库管理页、产品分类开关、多行文本批量导入/导出和运行时热重载。仍不包含系统文件选择器、网络导入、分享或云同步。人工规则不会写入 `user-model`，清空用户词频也不会删除用户词库；`#删` 不修改系统 bundle。Release 同时支持 `xiaohe` 与 `xiaohe-yinxing`，默认方案仍为 `xiaohe`。
