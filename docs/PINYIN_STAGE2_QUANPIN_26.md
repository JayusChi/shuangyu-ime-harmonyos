# 26 键全拼和 9 键计划阶段 2：26 键全拼完整链路

状态：`COMPLETED（主机自动化与 Release 构建范围）`  
完成日期：2026-08-10

## 目标与边界

本阶段正式交付 `quanpin-26`，复用现有 QWERTY 中文布局、二进制拼音词库、候选查询、整句解码、分页、提交和用户学习链路。9 键数字解析与九宫格 UI 仍保持禁用，留待阶段 3、4。

## 实现结果

### Rust 全拼解析器

- `QuanpinParser` 从 `pinyin-syllable` 的合法音节清单构建 Trie。
- 连续字母使用有界动态规划解析，最多保留 32 条稳定排序路径，不使用贪心切分或全字母组合爆炸。
- 完整音节优先选择较少音节的路径；`xian` 首选 `xian` 并保留 `xi'an`，显式 `xi'an` 则禁止跨边界合并。
- 最后一个音节可为合法前缀；例如 `zhon` 返回 incomplete/prefix 查询意图并召回 `zhong` 前缀候选。
- 原始输入历史由解析器持有，退格每次完整重算，因此删除字母或分音符后稳定恢复上一个状态。
- `displaySegments`、`currentPinyin` 和 `pinyinCombinations` 全部由 Rust 生成；C++ 与 ArkTS 未增加音节切分或路径排序。

### 候选、整句与提交

- `ImeEngine` 新增 `quanpin` 方案并通过既有 FFI/Node-API `changeScheme` 进入运行时。
- 单音节继续使用精确/前缀查询，多音节继续使用既有有界整句解码；多切分输入会查询首选路径并解码备选路径，再稳定去重。
- 修正整句候选的 `consumed_raw_len`：双拼仍按两码，全拼按实际拼音字母数，确保部分提交、剩余组合和连续退格不会删错字符。
- 候选点击、空格/回车首选提交、分页、部分提交和组合清空继续复用既有会话合同。
- 自动用户学习以 `scheme_id=quanpin` 隔离于 `xiaohe`。人工用户词库使用小写 `qp` 命名空间，例如 `自定义词<TAB>qpzidingyici`；旧双拼原始码规则不会被全拼解释。

### ArkTS 档案与入口

- `quanpin-26` 档案已启用，布局固定为现有 `qwerty-26-key`，引擎方案为 `quanpin`。
- 设置页改为统一“键盘方案”选择，直接持久化 `keyboardProfileId`。
- 空闲工具栏显示当前档案名称，并在统一选择面板提供“26 键全拼”；出现组合输入后仍隐藏方案入口，避免输入中途切换。
- Native 先切换、设置后保存、失败回滚的事务顺序保持不变；`pinyin-9` 仍登记但禁用。

## 实体键盘快速输入性能修订（2026-08-10）

用户在电脑实体键盘上快速连续输入后复现了明显队列积压，长组合还可能在候选消失后以原始英文字母结束。根因不是单独的解析器耗时，而是完整候选链和编辑器同步共同放大：每个完整全拼会逐一整句解码最多 32 条切分路径；`quanpin` 同时被强制放入兼容预编辑，每键需要读取光标、确认旧文本、选择范围并重写不断增长的整段字母。超过句子解码器的 64 字母边界后，失败结果会失去候选，随后空格/回车的无候选兼容路径可能结束原始字母。

修订结果：

- 12 字母以内最多解码首选加 3 条备选；更长组合只解码首选路径。Rust 仍返回有界 `pinyinCombinations`，`xian/xi'an` 等短歧义继续参与候选。
- 有完整覆盖、来源不含 fallback 的首选中文候选时，组合达到 24 字母后由下一字母触发一次原子自动提交；触发字母在同一 `CompositionResult` 中成为新段首键。fallback 永不自动提交，避免把未知拼音作为 ASCII 正文。
- 64 字母硬上限只在无法安全自动收口时生效，并在解析器变更前拒绝新键、保留原组合和候选。
- `quanpin` 与 `xiaohe` 一样优先使用编辑器原生 TextPreview。编辑器明确不支持时，兼容路径确认光标仍在范围末尾后只追加新增后缀；删除、候选替换和光标移动仍走完整范围校验。
- 实体按键消费和成功的逐键组合日志降为 debug；警告与错误仍保留原级别，Release 热路径不再同步产生两条 info 日志。

Release 完整引擎基线使用正式 `production.lex`，覆盖 `nihao`、`zhongguo`、22 字母句和 46 字母长句。修改前单轮 81 键耗时 6,671 ms，平均 `82.359 ms/键`；修改后 20 轮 1,620 键耗时 3,284 ms，平均 `2.027 ms/键`，约提升 40.6 倍。46 字母长输入由 `122.714 ms/键` 降至 `2.002 ms/键`，约提升 61.3 倍。最终记录为 0 失败、20 次中文自动收口、0 次 ASCII 自动提交。

全拼专项 `5/5`、`ime-engine`、`ime-ffi 29/29`、Rust fmt/Clippy、ArkTS 全量测试、双 ABI Native Release、unsigned Release HAP 和内容门禁均 PASS。当前 engine version 为 `0.0.1-pinyin-stage2-perf1`；HAP 为 38,261,216 bytes，SHA-256 `98DFB338B502055FBE87D69F165F73B5BD4E07B7A83F6E5FD5EF5A6CD5AC343F`。实体键盘设备复测为 `NOT_RUN`。

## 全拼质量修订（2026-08-11）

设备反馈证明 24 字母自动收口不符合传统全拼的用户预期，本修订明确替代上一节对应策略：

- 删除全拼长度触发的自动提交；长组合只有候选选择、空格、回车或标点等明确用户动作才能上屏，64 字母安全门禁继续保留当前组合而不提交原始字母。
- `n` 既是词库中的独立读音又是大量音节的声母前缀。解析器保留完整状态，同时使用前缀召回；独立读音“嗯/唔”按频率参与排序，不再硬排在“你、那、能”等常用前缀候选之前。
- 正式项目自有短句由 7 条扩展为 76 条，总词条 65,191；新增星期、日常问答、消息、文件和输入法场景，正式二进制为 3,741,151 bytes，SHA-256 `D1B1A3CFFD1784FD3ABDAE1A3DAB4189FF9CE87BA2431D83F0B92A1B7356D9C5`。
- 整句解码器从正式词库的多字词确定性构建字符二元上下文模型，只在词边界加分，并允许最长 9 音节正式短句形成单边；不读取网络、商业输入法数据或运行时文本词库。
- ArkTS 在编辑器预编辑异步确认前先发布同步候选结果，写入失败仍按原合同回滚，输入动作继续严格串行。

生产词库真实句专项覆盖 `今天星期一`、`你为什么这样说`、`这个是什么意思`、`收到以后请回复`、`输入法不要自动上屏` 等首选结果，以及长组合零隐式提交。该轮 engine version 更新为 `0.0.1-pinyin-stage2-quality3`。

## 全拼质量修订 quality4（2026-08-11）

- 部分候选提交后，旧候选会话先清空，再仅以未消费的 raw input 建立新候选快照，禁止已提交前缀候选残留到下一段。
- ArkTS 默认候选页调整为 7 项；浮动候选窗返回完整内容估算宽度，窗口控制器再按设备屏幕安全区限宽。

- engine version 更新为 `0.0.1-pinyin-stage2-quality4`。
