# 用户词库覆盖层格式

## 文件与字段

用户词库是独立于 `production.lex` 和 `user-model` 的 UTF-8 文本文件。首行可带 UTF-8 BOM，输入支持 LF、CRLF、空文件和末行无换行；规范化保存使用 UTF-8、LF、无 BOM。

每个非空数据行必须恰好包含一个 TAB：

```text
词条<TAB>编码
上屏内容<TAB>编码#直
上屏内容,候选提示<TAB>编码#直
词条<TAB>编码#删
词条<TAB>编码#固
词条<TAB>编码#N
```

编码沿用第一阶段的严格规则：1～64 个小写 ASCII 字母。词条沿用文本码表的常用 CJK、最多 32 字符规则。`#直` 的候选提示为可选展示元数据，最多 64 字符；省略时直接显示上屏内容，带逗号时逗号两侧均不得为空。空格不能代替 TAB，多余字段、空字段、未知标记、多个标记、标记位于中间、非法 UTF-8 和非法编码都会被拒绝；诊断包含路径、物理行号、字段和原因，但不回显整行私人内容。

### 全拼方案命名空间

阶段 2 为 `quanpin` 使用 `qp` 代码前缀，前缀属于持久化编码但不会显示为候选读音：

```text
自定义词<TAB>qpzidingyici
全拼固顶词<TAB>qpquanpingudingci#固
```

因此旧小鹤双拼规则 `ni` 只作用于 `xiaohe`，全拼规则 `qpni` 只作用于 `quanpin`。显式分音符不写入人工编码；`xi'an` 的人工规则写作 `qpxian`。该约定保持现有两字段格式和原子保存合同不变，并为后续方案保留独立命名空间。

## 五种规则

- 无标记：增加普通用户候选；同码的系统候选全部排在它之前。
- `#直`：增加用户可管理的直通候选。精确输入时上屏内容取逗号前文本；精准前缀提示可显示逗号后的候选提示并优先于普通长码提示；万能键不枚举直通词条。它与普通词条使用相同的“完整编码＋上屏内容”覆盖键，可在管理页新增、修改动作或删除。
- `#删`：只隐藏完全相同的“当前编码＋词条”，不修改系统二进制词库，也不影响其他编码下的同名词。
- `#固`：固定在同码最终候选的最前方；多个固顶按最终有效规则的 `source_order` 排列。
- `#N`：放在最终同码列表从 1 开始的第 N 位；位置类型为 `u16`，合法范围为 1～65535。`#0`、负数、正号、小数、空数字和溢出均非法。

同一文件内重复出现相同“编码＋词条”时，后出现的有效规则覆盖先前规则，并保留后一条的 `source_order`。快照按最终有效记录的源顺序保存，不依赖哈希遍历顺序。

## 硬排序

系统基础频率、整句评分和 `user-model` 学习先完成软排序，再按以下顺序应用人工规则：

1. `#删` 过滤精确的编码＋词条；
2. 保留系统候选的软排序，并将普通及直通用户候选追加到全部同码系统候选之后；重复文本由用户来源替代系统来源并按用户候选处理；精准前缀提示路径单独将直通提示置于普通长码提示之前；
3. 建立 `#固` 保护前缀；
4. 放置 `#N`；
5. 稳定去重；
6. 最后执行数量限制与候选会话分页。

多个规则请求同一有效位置时按 `source_order` 连续放置。超出列表长度的位置稳定追加。`#固` 优先于 `#N`：

```text
effective_position = max(N, fixed_count + 1)
```

因此任何 `#N` 都不能插入固顶前缀。位置是完整候选列表中的全局位置，不是当前页位置。

精确/前缀路径保持“精确优先、没有精确规则才使用更长编码前缀”。空输入不枚举整个用户词库。生产小鹤双拼保留系统软排序，不把系统候选切换为码表顺序；下述两码固顶简拼另外参与句内解码。

## 小鹤双拼句内固顶简拼

在“词库与个性化 → 我的词库”新增词条“双拼”、编码 `up`，动作选择“固顶”，即可在句中使用。文本文件写法仍为两字段，中间是 TAB：

```text
双拼	up#固
怎么	zm#固
```

小鹤 `up` 不能组成合法的声母＋韵母音节，解析为 `sh`、`p` 两个声母。符合下列条件时，固顶二字词会成为整句解码中的固定片段：

- 仅在小鹤双拼 `xiaohe` 生效，编码为两码，词条恰为两个汉字，动作为 `#固`。
- 两码处在从当前组合起点计算的第 1–2、3–4、5–6……位；分音符不计入码位，不能在这两码中间强插分音符。
- 两码本身不能组成合法完整音节。合法声韵组合仍按原音节处理，跨两码边界的同字母片段不会替换。
- 同码存在多个有效二字固顶时，句内固定使用源顺序最前的一条；单独输入该码仍保留原固顶候选列表。

例如 `uphfhc → 双拼很好`、`woysup → 我用双拼`、`upup → 双拼双拼`；增加 `怎么<TAB>zm#固` 后，`nizmbuxk → 你怎么不行`，也支持 `ni'zm'bu'xk`。固定片段不可被系统长词跨越或拆开。可以通过修改、删除该规则改变句内结果；保存后热重载生效，重启后保留。普通添加、`#N`、直通及超过二字的词条仍按原有整码候选规则处理。人工固定片段不写入用户词频学习。

## 独立码表运行时接入

阶段 11.6.4 复用同一解析器、规则模型和不可变快照，不新增文件格式或码表专用解析器。系统码表先按分类顺序与分类内 `source_order` 形成完整候选，再应用本文件的硬排序，最后才限量和分页。

正式 `xiaohe-yinxing` 的规则源固定为两层：冻结包内 `user-rules.txt` 先进入基础快照，外部 `userLexiconPath` 后进入覆盖快照。合并键是“完整编码＋词条”，后层覆盖前层，新的稳定 `source_order` 按内置有效规则后接外部有效规则重建。缺失、空或双损坏外部文件等价于空外层，不能移除内置规则；外部有效备份恢复后仍覆盖内置同键规则。外部文件使用同词同码的 `#删` 可以隐藏包内直通词条，改回 `#直` 可重新增加或覆盖；管理页新增、修改和删除的仍是普通数据词条，不会改写应用功能。`code-table-fixture` 不含包内层，保持原有外部快照语义。

码表候选保留自己的完整编码。`#删` 只删除完全相同的“候选完整编码＋词条”，因此前缀查询时不会误删其他更长编码下的同名词；如果当前精确系统候选被删空，也不会在同一次查询中重新混入更长系统前缀。普通、直通、固顶和位置规则仍按既有 exact-or-prefix 快照选择语义参与当前查询，后规则覆盖不变。分类源和外部文件里的 `#直` 都以独立 `Direct` 动作保存，正式转换不得把标记抹成普通 `Add`；旧 bundle 中带“分类归属＋Add”的历史直通记录仅作为向后兼容读取。

分类词库本身就是成品输入。转换器逐文件接收 `#直`，保留原词条、编码、候选提示、来源分类和 `Direct` 类型，不需要人工搜索后固化。`$cmd/$ddcmd`、网址打开、系统设置等是另一条功能动作链，只能按独立白名单实现，不能通过补 `#直` 伪装成词条。

引擎创建时完整解析一次用户文件，并用 `Arc<UserLexiconSnapshot>` 在只读查询间共享。reset、候选会话重建、清空 `user-model` 和方案切换只清组合状态，不清用户规则；新句柄或新进程从同一路径重新加载。管理页面保存后可显式热重载，完整加载成功才原子替换快照；主文件损坏时优先恢复备份，运行中双损坏保留最后有效快照且系统码表仍可查询。

## 保存、备份与恢复

正式管理接口为文档级 compare-and-swap：读取返回规范化内容对应的稳定 `revision`；保存必须携带该 revision。若磁盘已经被其他窗口或进程更新，返回 `revision_conflict`，不进入替换流程。空文件和不存在文件也有稳定 revision，因此首次创建与清空使用同一合同。

主文件的同目录辅助文件为：

```text
user_lexicon.txt
user_lexicon.txt.tmp
user_lexicon.txt.bak
user_lexicon.txt.old
```

保存先完整写入 `.tmp`，执行 `flush` 和 `sync_all`，重新解析校验后才切换。已有主文件先形成并同步备份，再移到可回滚的 `.old`，最后把 `.tmp` 改名为主文件；任何失败都会清理临时文件并尽量恢复旧主文件。Windows 和 HarmonyOS/Linux 均不采用“先删除主文件再逐行写入”。同一快照重复保存产生相同规范化字节。

加载行为：

- 主文件有效：加载主文件；
- 主文件和备份都不存在：空覆盖层；
- 主文件损坏、备份有效：加载备份并返回 `LoadedBackup` 与脱敏警告码；
- 主文件与备份都损坏：初次加载使用空覆盖层，系统候选仍可用；
- 已有运行时快照的 reload 失败：保留最后一个有效快照。

运行时只使用完整解析后生成的不可变快照，不在按键热路径读盘或解析文本。Release 日志不得输出完整词条、整行内容或整个用户词库。

## 当前阶段边界

阶段 12 已提供正式用户词库管理页、产品分类开关、多行文本批量导入/导出和运行时热重载。仍不包含系统文件选择器、网络导入、分享或云同步。人工规则不会写入 `user-model`，清空用户词频也不会删除用户词库；`#删` 不修改系统 bundle。Release 同时支持 `xiaohe` 与 `xiaohe-yinxing`，默认方案仍为 `xiaohe`。
