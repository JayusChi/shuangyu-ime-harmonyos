## 交付阻塞：导入成功不等于实际生效

平板操作链：浏览器将结构第一行改为 W/Q、空格宽度改为 6.3、文字改为 TEST，配色改为樱花粉；分别导出并在 App 中导入。App 提示“已导入并应用”，设置记录也已选择对应 ID，但另一个应用唤起输入法后仍显示默认键序、默认颜色与“空格”。

输入法扩展日志报告 `KeyboardCustomizationRepository` 读取自定义结构和皮肤失败，错误码 `13900002`（文件不存在）。设置主入口与输入法扩展均打印类似的沙箱路径，但它们属于不同独立沙箱。仅统一 EL2 或更换普通 context 不能解决文件共享；相关试验性目录改动已撤回，没有保留会迁移或隐藏已有模板的临时方案。

原始验收时，`module.json5` 没有为输入法扩展配置 `dataGroupIds`，本地受检的开发与发布 profile 也没有 `data-group-ids`。当时模板仓库按 `context.filesDir` 读写，尚未接入输入法共享沙箱。华为文档明确说明主入口与输入法扩展的独立沙箱不能互访，共享文件需使用配置后的共享沙箱及 `getGroupDir`。参见[华为输入法安全模式与共享沙箱说明](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-V5/ime-kit-security-V5)。

后续必须取得/确认获批的 data-group-id 与对应签名 profile，启用已补齐的共享目录接入代码，并在三个设备类别复验“编辑 → 下载 → 导入 → 实际键盘显示”，包括基础模式、旧模板迁移及同 ID 覆盖刷新。本次没有提交外部申请或伪造 data-group-id。
