# 2026-09-15 候选显示与嵌入编码反馈修复

## 本次修改

### 浮动候选对齐

`FloatingCandidateRoot` 的横向 Scroll 原来没有指定子内容对齐方式。窗口为避免输入时抖动会保留本次组合的最大宽度，候选减少后剩余空间使内容居中，编码左侧和首候选位置随之变化。

现在滚动内容显式左对齐，候选行从左开始排列，编码文字左对齐并保留固定的左右内边距。窗口原有的字号、固定行高和组合期间不收窄行为继续生效。

### 实体键盘分页

原来的 `[` / `]` 已经路由到翻页操作，但引擎默认一次返回 50 项，界面默认仅显示 5 项。直接翻引擎页会绕过当前批次里未展开的候选。

现在实体模式在每个引擎批次内按用户设置的显示数量切页，当前批次全部看完后再请求下一批。返回上一批时落在其最后一个显示页。每页从 1 重新编号，数字键、鼠标点击、空格和方向键共用当前页候选；提交时映射回原引擎下标。小鹤音形先筛选可见候选再分页，避免提示项占用错误下标。触屏仍可使用原来的展开面板。

实体模式同时禁用展开入口、自动展开和状态层的展开操作。设置项说明更新为实体键盘按 `[ ]` 翻页。

### 编码嵌入输入框

入口：**设置 → 候选 → 编码嵌入输入框**。默认关闭，从下一次组合输入开始生效；选择会保存并通过现有设置同步链传递。

启用条件：用户开启，且当前编辑器声明支持系统预编辑、不是密码输入框。仅调用系统 `setPreviewText` 管理预编辑范围；编辑器不支持或返回明确的 `12800011` 时使用原有候选区域回退，不把字母通过普通 `insertText` 写进正文。选词先替换预编辑范围再结束预编辑，取消先清空范围再结束。光标/设置类功能候选执行前清理嵌入预编辑。

## 录屏研究与边界

已逐帧查看用户提供的 GIF 和 13.75 秒 MP4。GIF 用于确认编码和候选沿左侧排列的目标；MP4 展示从候选窗编码切换为编辑器光标处编码，以及选词后的中文结果。

现有代码中有旧的普通文本兼容插入/选区替换路径，也有依赖宿主的原生预编辑路径。前者容易受到光标返回延迟、选区变化和普通文本样式的影响；后者的字体、下划线及输入框布局由宿主管理。本次开关只开放原生预编辑路径，并保留能力不足时的回退。

仅凭录屏不能确定客户宿主是否错误声明预编辑能力，也不能证明其第一字母样式或替换时序已修复。需要在客户同一应用和设备上验收。分段选词后，现有原子提交链会把尚未选择的剩余编码保留在候选区域；该兼容行为继续保留。

API 依据：[OpenHarmony InputClient 预编辑接口说明](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/reference/apis-ime-kit/js-apis-inputmethodengine.md#setpreviewtext12)：`setPreviewText` 替换预编辑范围，`finishTextPreview` 会正式提交范围内容。因此取消不能直接调用结束预编辑，不能把正文中可见的字母一概视为已正式上屏。

## 手工验收

1. 浮动模式输入 `f → fi → fih → 回删`，确认编码两侧内边距稳定、候选减少后从左侧排列。
2. 实体模式分别设置 3、5、7、9 个候选，用多候选编码反复按 `]`、`[`，再用数字键和空格选词；应保持横排且不漏词、不提交相邻页候选。
3. 在支持预编辑的输入框开启嵌入编码，已有中文后输入 `kj → kjk → 回删 → 选词`，再输入并按 Esc 取消；确认正文保留正确中文，无多余字母。
4. 在不支持预编辑的宿主重复步骤 3，应看到编码回退至候选区域。
5. 重启输入法/应用，确认嵌入编码开关和候选数量保持；密码框不启用嵌入编码。
