# 0.6.0 客户反馈第 1～6 点：实体键盘合同

## 范围

客户已明确第 1～6 点全部针对实体键盘。验收必须从 HarmonyOS 实体按键回调进入 `InputMethodLifecycleDispatcher` 和 `KeyboardController`；触屏键盘行为只能作为兼容回归，不能替代实体键盘证明。

## 行为矩阵

| 序号 | 实体键盘输入 | 期望行为 | 实现边界 |
| --- | --- | --- | --- |
| 1 | `;` 后输入一个快符字母 | 唯一精确静态快符随字母直接上屏，不再补空格 | 实体字母进入串行队列，正式码表引导状态只对唯一精确静态文本自动提交；功能动作仍等待确认 |
| 2 | 有且只有一个普通候选时按 `;` | 先顶首选，再进入分号引导 | `handlePhysicalCodeTableSemicolon` 在队列执行时重新读取实时候选，不能使用按键到达前的旧快照 |
| 3 | 空组合按 `;`、再按空格或再次按 `;` | 单分号显示 `：`；空格上屏 `：`；双分号上屏 `；` | 正式快符保留码为 `_ → ：`、`; → ；`，第二次实体分号仍走码表状态机 |
| 4 | 单击 `o`，或依次输入 `o`、`k` | 原始码严格为 `o`、`ok`，不能出现 `oo`、`okk`；后续 `o` 前缀词条和动作保持可达 | 新旧实体按键 API 按 `(keyCode, DOWN/UP)` 在 80 ms 窗口内一次性配对；同通道长按重复不被抑制 |
| 5 | 输入分类 `#直` 或 `5.直通.txt` 中的动作编码 | 分类文件直接作为成品数据来源；受支持词条可通过增删源行管理，不再逐编码固化 | 分类 `#直` 保持 `Direct` 类型并支持外部 `#删`；动作直通保留客户编码、候选和顺序，离线转为封闭类型。当前 44 行接受 31 行、隔离 13 行，运行时不解释 `$cmd/$ddcmd` |
| 6 | 输入码与候选同处实体键盘浮动候选窗 | 输入码不显示下划线 | `CompositionPreeditPlacement.FLOATING_WINDOW → NONE`；嵌入/固定展示位仍为 `UNDERLINE`，两者都不修改组合数据 |

## 实体按键去重合同

HarmonyOS PC 宿主可能同时派发现代 `keyEvent` 和旧版 `keyDown/keyUp`。两套回调不保证同相位相邻，可能出现：

```text
modern DOWN(o) → modern UP(o) → legacy DOWN(o) → legacy UP(o)
```

去重器必须保留最近的按键码、按下/抬起相位、通道、处理结果和时间；另一通道命中相同按键码与相位后复用原处理结果，并消费该记录。不能只记最后一个回调，否则 `modern UP` 会覆盖 `modern DOWN`，随后 `legacy DOWN` 会再次把 `o` 送进引擎。

## 验证

- ArkTS 全量单元测试构建与执行：PASS。
- 码表转换器：24/24 PASS。
- 码表运行时：104/104 PASS（含生产直通数据安全校验）。
- 正式小鹤音形引擎：19/19 PASS。
- x86_64 / arm64-v8a OHOS Native：PASS。
- x86_64 2in1 模拟器系统按键注入与浮动窗视觉验收：PASS。`uitest keyEvent` 从实体按键路由进入，逐项通过 `;q`、唯一候选后 `;`、`; Space`、`;;`、`o`、`ok`、分类 `#直` 与客户 `5.直通.txt` 动作词条；Phone 固定候选栏对照仍显示输入码下划线。证据见 `docs/evidence/2026-08-31-v0.6.0-physical-keyboard/`。
- 真实 USB/蓝牙/内置实体键盘：NOT RUN。模拟器注入不能替代新旧按键 API 双通道真实时序的最终证明。

最终硬件复验仍必须使用真实 USB/蓝牙/内置实体键盘，至少录制 `;q`、唯一候选后 `;`、`; Space`、`;;`、`o`、`ok`、一个分类 `#直` 编码，并截取浮动窗无下划线画面。
