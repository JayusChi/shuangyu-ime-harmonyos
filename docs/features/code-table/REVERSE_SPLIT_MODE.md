# 三/四码逆切分模式

客户于 2026-09-07 确认音形四码空码的自动 `2+2` 切分，并于 2026-09-08 补充：三码为空码且不存在有效后续编码时，立即自动按 `2+1` 开始切分。

## 用户行为

- 设置页“音形输入 → 切分模式”为独立开关，默认关闭（传统）。旧设置迁移也保持传统。
- 输入 `oit`，前两项为 `1.[传统]`、`2.[切分]`；与设置页共用同一个持久化状态。原有同码符号继续排在后面。
- 切分模式下，四码没有精确候选且不存在有效的长码续码时，查询前两码和后两码的精确二简。任一半为空时继续执行原有的空码清除/保留规则。
- 输入到三码时，如果三码没有精确候选且不存在有效的长码续码，查询前两码和末尾一码的精确候选并立即显示 `2+1` 切分；例如 `jda` 显示为 `jd'a`，候选显示“简单啊、安装”。若三码本身有候选或仍有后续编码，则保持原有输入路径。
- 前两码始终取首选；后两码只有一个候选时，按既有“四码唯一自动上屏”设置提交完整组合。关闭唯一自动上屏时保留候选，继续输入第五个字母仍顶首选。
- 后两码有重码时，按现有候选页大小显示并可翻页；第一项显示完整组合，其他项仅显示后半部分。选择任意项均提交完整的“前两码首选＋后两码所选项”。
- 第五码提交前后首选，且第五个字母成为下一组的首码；即使翻到其他候选页，也仍顶第一组首选。
- 三码 `2+1` 是无第四码时的候选状态。继续输入第四码时不提交三码候选，而是把完整四码重新交给原有四码精确候选、有效长码后续、`2+2` 切分或空码清除规则处理。
- 字、词和普通符号二简均可参与。沿用当前已启用分类、系统顺序和用户词库排序/删除规则。功能动作和前缀提示不作为二简文本拼接。
- 切分状态显示为 `hf'kn`，原始输入仍为 `hfkn`。退格回到 `hfk`，重新输入可再次切分；不会提前把“很”写入编辑器。
- 切换模式会清除当前未上屏组合。手动切分、强制拆分已有四码词和其他拆分比例不在本次范围内。已有长码、OK 拼字和直通续码路径继续优先。

## 示例

| 编码 | 首选结果 |
| --- | --- |
| `alyghfry` | 按理应该很容易 |
| `gmycxnta` | 干嘛要笑她 |
| `xtupjdma` | 学双拼简单吗 |
| `nivtsmne` | 你折腾什么呢 |

`hfkn` 的候选显示为“很可能、困难”，选择第二项提交“很困难”；继续输入 `n` 则提交“很可能”，保留新的组合码 `n`。

`jda` 在不存在三码精确候选和有效后续编码时，候选显示为“简单啊、安装”；候选实际提交内容分别为“简单啊、简单安装”。

## 接口与数据

- 设置 schema 20：`codeTableReverseSplitEnabled: boolean`，默认 `false`。
- 既有 `setCodeTableCommitPolicy` JSON 增加可选 `reverseSplitEnabled` 布尔值，缺省 `false`；C ABI 函数签名不变。
- 模式动作：`DIRECT_CONTROL`，`formatId=settings.split-mode`，`text=traditional|split`。动作选择只返回设置命令，不把候选标题上屏。
- 合成候选 `source=reverse-split`、`reading=完整四码`、`consumedRawLen=4`；`text` 始终为完整组合，`displayText` 控制候选显示。使用既有选择、提交和撤回链路。
- `oit` 沿用直通表导入流程：`5.直通.txt` 新增 `$cmd(set(ime-split=0),[传统])` 和 `$cmd(set(ime-split=1),[切分])`。这两个操作由导入器转换为上述类型化动作，不执行原始命令。当前 46 行中接受 33、隔离 13；字词 bundle 无须重建。
