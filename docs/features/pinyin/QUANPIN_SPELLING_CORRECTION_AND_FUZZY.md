# 26 键全拼有界拼写纠错与可配置模糊音

## 结论

本实现为正式 26 键全拼链路增加了默认关闭的有界拼写纠错和八项独立模糊音。功能开启后的 dev 评测在不降低 clean Top1/Top3/Top5 的前提下，将总体 Top5 从 66.667% 提升到 72.333%，typo Top5 从 0% 提升到 44.444%，fuzzy Top5 从 16.667% 提升到 91.667%。功能全部关闭时，完整候选结构与顺序的 SHA-256 和改动前完全一致。

这是一次受冻结数据、生产词库和确定性安全合同约束的能力改进，不代表已达到成熟商业输入法水平。拼写纠错的开发机 Release 延迟仍有明显代价，真实设备体验尚未验证。

## 2026-08-18 延迟治理

第一轮性能治理不修改编辑距离、错误类型、生产词库或跨层配置协议，主要消除纠错路径的重复工作：

- `QuanpinParser` 的音节 Trie 改为进程级只读共享，不再为每个拼写变体重建约 400 个音节的索引；
- 变体按既有确定顺序流式生成、解析，到节点/变体上限立即停止，不再先构造完整临时候选池；
- 增加容量 32 的解析扩展 LRU；不可变词典查询缓存跨 composition 保留，退格、重输和相同前缀可以复用；
- 只有无高置信完整候选时才启动拼写纠错；已有可用候选且尾部只是单字母合法音节前缀时，延后到后续按键；
- 全部纠错路径仍先执行便宜的精确词典查询；只有精确无结果才进入句子解码，四种错误按 `多字/漏字/邻键/错序 = 4/2/2/2` 分配独立预算；
- Rust 只序列化当前页候选，正式 ArkTS 页大小为 7；C++ 转换器按 JSON 候选数预留容量并移动已解析字段，避免 vector 扩容和额外的字符串拷贝。审计确认该跨层路径有严格小页上限，不是本轮 Rust 长尾的主因，因此不扩大 ABI 改造范围；
- 候选合并、稳定去重、`rawInput`、`consumedRawLen`、自动上屏和分页合同不变。

HarmonyOS 预编辑提交侧同时取消固定 80 ms 睡眠：`finishTextPreview` 返回后先读取光标确认状态，未确认时每 8 ms 短轮询，80 ms 仅作为最长兜底窗口。状态读取失败不会重试任何编辑器写入。

## 实现范围

### 拼写纠错

仅处理编辑距离 1，并支持：

- 漏字：向原始串插入一个字母；
- 多字：从原始串删除一个字母；
- QWERTY 邻键误触：使用固定、对称、可测试的键位邻接表替换一个字母；
- 相邻字母错序：交换一对相邻字母。

生成结果必须能解析为合法完整拼音路径。纠正串只用于候选查询，永不写回 `rawInput`；候选的 `consumedRawLen` 使用原始输入长度。继续输入、退格、reset 和方案切换都会重新计算或清除功能候选，不保留陈旧快照。

### 模糊音

下列八项可独立开启，默认全部关闭：

- `n_l`
- `z_zh`
- `c_ch`
- `s_sh`
- `in_ing`
- `en_eng`
- `an_ang`
- `ian_iang`

转换发生在合法拼音音节及音节边界层，不对任意字母串全局替换。每条冻结 fuzzy 样本在评测时只启用其声明的 `enabledFuzzyOptions`。

### 合并和排序

候选按确定性层级生成：原始路径、单模糊音、多模糊音、编辑距离 1 纠错、纠错与模糊音组合。原始高置信候选设有保护窗口：通常保护前三位；原始输入为合法完整拼音时保护前五位。之后才允许功能候选进入，最后追加其余原始候选。

采用这个有限保护窗口，是为了同时保护 clean 的可见高质量候选并让错误输入的有效纠错结果有机会进入 Top5。完整 dev 结果证明 clean Top1/Top3/Top5 均未下降；clean MRR 从 0.705328 小幅变为 0.704421，原因是保护窗口之后的低位候选可能被功能候选后移，报告不将该变化隐藏。

相同可见文本使用稳定去重：优先保留更高层级来源；若陈旧前缀候选消费的原始输入更少，允许消费完整原始串的功能候选替换它。候选 ID、顺序和三轮完整输出均确定。
