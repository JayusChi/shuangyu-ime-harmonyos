### 二、已支持功能详细说明

#### ✅ 功能③：成对符号光标居中

**实现位置**：
- `entry/src/main/ets/application/ProtocolActionExecutor.ets`
- `entry/src/main/ets/infrastructure/ime/ImeConnectionService.ets`

**工作原理**：
引擎返回 `INSERT_PAIR` 协议动作时，系统会：
1. 插入成对符号（如`""`）
2. 计算光标应该定位的位置（UTF-16偏移量）
3. 调用 `inputClient.selectByRange()` 定位光标

**使用方式**：
在码表或引擎逻辑中定义触发条件，引擎返回 `InsertPairAction` 即可。

#### ✅ 功能⑤：分类词库管理

**实现位置**：
- `entry/src/main/ets/infrastructure/native/NativeEngineTypes.ets`
- Native引擎（Rust部分）

**支持的词库分类**：
- `PRIMARY`：主词库（必需）
- `PRIMARY_EQUIVALENT`：主词库等价扩展
- `EXTENSION`：扩展词库
- `USER`：用户词库
- `FUNCTIONAL`：功能性词库（符号等）

**API接口**：
```typescript
// 获取词库配置
getCodeTableCategoryConfig(handle: number): CodeTableCategoryConfig;

// 设置启用的词库分类
setCodeTableCategories(handle: number, enabledCategoryIds: string[]): CompositionResult;
```

**特性**：
- 动态启用/禁用，实时生效
- 支持设置默认启用状态
- 必需词库不可禁用
- 每个分类有独立的元数据（名称、词条数等）

#### ✅ 功能⑥：用户词库导入

**实现位置**：
- `entry/src/main/ets/application/UserLexiconController.ets`
- Native引擎接口

**支持的操作**：
```typescript
// 加载词库文件
loadUserLexicon(path: string): UserLexiconDocument;

// 保存词库文件
saveUserLexicon(path: string, expectedRevision: string, content: string): UserLexiconDocument;

// 重新加载词库
reloadUserLexicon(handle: number): CompositionResult;
```

**词条动作类型**：
- `ADD`：添加新词
- `DELETE`：删除词条
- `FIXED`：固定位置（优先级最高）
- `POSITION`：指定候选位置

**词库格式**：
支持标准的码表格式，包含：
- 词语、编码、权重
- 错误验证和行号定位
- 版本控制（revision）

### 三、不支持功能及原因分析

#### ❌ 功能①：重复上屏

**不支持原因**：
- 当前没有"上屏历史记录"机制
- 没有保存最近提交文本的状态

**技术可行性**：✅ 完全可行

**实现方案**：
1. 创建 `CommitHistoryManager` 维护循环缓冲区
2. 每次 `commitPreviewText`/`insertText` 时记录
3. 添加 `REPEAT_LAST_COMMIT` 键盘动作
4. 可通过特殊编码触发（如：rqt）

**实现难度**：🟡 中等（纯业务逻辑，无API限制）

#### ❌ 功能②：撤销上屏

**不支持原因**：
HarmonyOS InputMethodEngine API的根本限制：
- 没有 `undoCommit()` 类似的API
- 已提交的文本无法直接撤销
- 只能通过 `deleteForward(length)` 间接删除

**技术可行性**：🟡 部分可行，但有严格限制

**限制条件**：
1. ✅ 可以删除指定长度的文本
2. ❌ 需要精确知道上屏文本的UTF-16长度
3. ❌ 必须假设用户没有移动光标
4. ❌ 表情符号、组合字符可能导致长度计算错误

**建议的实现方案**：
1. 记录上屏文本和长度
2. 限制撤销时间窗口（如5秒内）
3. 先验证：读取光标前的文本，比对是否一致
4. 一致才执行删除操作

**实现难度**：🔴 较高（需要复杂的边界处理）

#### ❌ 功能④：模拟End键

**不支持原因**：
HarmonyOS InputMethodEngine API根本不支持模拟物理按键。

**API限制**：
`inputClient.sendKeyFunction()` 仅支持：
```typescript
ENTER_KEY_TYPE_NEWLINE   // 换行
ENTER_KEY_TYPE_SEARCH    // 搜索
ENTER_KEY_TYPE_DONE      // 完成
ENTER_KEY_TYPE_NEXT      // 下一个
ENTER_KEY_TYPE_GO        // 前往
ENTER_KEY_TYPE_SEND      // 发送
```

**无法实现的按键**：
- ❌ 方向键（↑↓←→）
- ❌ Home/End
- ❌ PageUp/PageDown
- ❌ Esc、Tab
- ❌ 功能键（F1-F12）

**技术可行性**：❌ 完全不可行（API缺失）

**替代方案**：无

#### ❌ $cmd()直通编码语法系统

**不支持原因**：
当前引擎架构不支持"命令"概念：
- 码表条目直接映射到候选词文本
- 没有命令解析器
- 没有命令执行框架

**技术可行性**：✅ 可行，但工程量巨大

**需要的改造**：
1. **命令解析器**：
   - 正则匹配 `$cmd(...)` 语法
   - 解析参数和标签
   - 验证语法正确性

2. **命令执行器**：
   - 根据命令类型分发执行
   - 支持异步操作
   - 错误处理和超时保护

3. **引擎集成**：
   - 修改候选生成逻辑
   - 区分普通候选和命令候选
   - 命令候选被选中时执行，而不是上屏

4. **扩展机制**：
   - 支持注册自定义命令
   - 插件化架构

**实现难度**：🔴 非常高（需要架构级改造）

**参考实现**：类似 Rime 的 lua 扩展机制

### 四、HarmonyOS输入法API能力边界

为了让您更清楚地了解技术限制，这里总结HarmonyOS输入法API的能力范围：

#### ✅ 支持的操作：

1. **文本输入**：
   - `insertText(text)` - 插入文本
   - `setPreviewText(text, range)` - 设置预览文本（组合区）
   - `finishTextPreview()` - 提交预览文本

2. **文本删除**：
   - `deleteForward(length)` - 删除光标前N个字符
   - 需要知道精确的UTF-16长度

3. **光标控制**：
   - `getTextIndexAtCursor()` - 获取光标位置（绝对索引）
   - `selectByRange(range)` - 设置选区/光标（绝对位置）

4. **文本查询**：
   - `getForward(length)` - 获取光标前的文本
   - `getEditorAttributeSync()` - 获取编辑器属性

5. **功能键**：
   - `sendKeyFunction(keyType)` - 仅支持回车键变体

#### ❌ 不支持的操作：

1. **模拟按键**：
   - ❌ 无法发送方向键、Home/End等
   - ❌ 无法模拟组合键（Ctrl+X等）

2. **相对光标移动**：
   - ❌ 无法 "光标左移1格"
   - ❌ 只能设置绝对位置

3. **撤销/重做**：
   - ❌ 没有 undo/redo API
   - ❌ 无法知道编辑器的撤销栈

4. **剪贴板**：
   - ❌ 无法读取剪贴板内容
   - ❌ 无法写入剪贴板

5. **文本选择控制**：
   - ❌ 无法 "全选"
   - ❌ 无法 "选中某个单词"
