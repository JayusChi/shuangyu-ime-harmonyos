# 阶段 11.6.1 码表输入行为与状态机规范

## 阶段 11.6.6 补充：引导与动作

- Rust 状态枚举冻结为 `Idle / NormalCode / GuidePrefix / GuideCode`。
- 分号进入或重启引导；空引导只查询快符表的 `_` 默认项；引导编码只查询独立 guide/action 表。
- 普通状态永不查询引导表，引导状态永不查询八个普通分类。
- 快符保持动作表源顺序，完整合并后再分页，不经过小鹤双拼排序或用户模型。
- 静态文本、静态符号和快符选择后返回 `commitText`；日期时间和成对符号返回唯一 `action`。
- 每次选择最多产生一个非空可见提交，`commitText` 与 `action` 互斥。
- reset、方案切换、会话结束、编辑框切换、键盘隐藏和销毁清除引导状态。
- 引导状态不触发四码自动上屏、第五码切分或空码切分。

完整逐分支表见 `GUIDE_STATE_TRANSITIONS.md`；正式能力与数据缺口见 `STAGE11_6_6_CAPABILITY_MATRIX.md`。

状态：阶段 11.6 已于 2026-07-22 重启。11.6.3 正式小鹤音形系统查询回归、11.6.4 包内/外部用户规则分层、11.6.5 产品分类合同与运行期选择，以及 11.6.6 引导与封闭动作运行时均已完成。11.6.7 已实现本规范冻结的自动上屏、顶屏、第五键单次重放与空码清屏；正向/反向空码切分因缺少权威细则保持阻塞，见 ADR 0018。

## 1. 术语与不可变量

- `rawCode`：码表后端持有的普通原始编码，不含分号引导前缀。
- 空字符串：`rawCode == ""`。结果必须为空候选，禁止枚举全表。
- 精确词条：词条完整编码等于当前非空 `rawCode`。
- 有效更长编码：在本次启用分类不可变快照中，以 `rawCode` 开头且长度更长，并在适用的用户硬规则后仍可形成候选的编码。
- 最终精确候选：当前精确查询结果经过 `#删`、普通用户词、`#固/#N` 和稳定去重后的精确候选。
- 精准匹配提示：正式 `xiaohe-yinxing` 在当前编码没有系统精确词条及用户精确规则时，从有效更长编码中按词库源顺序返回的有界、可主动选择候选；它不是最终精确候选。
- 空码：`rawCode != ""`，最终精确候选为空，且不存在有效更长编码。空码不等于空字符串。
- 一次操作：一次 `processKey`、`backspace`、候选选择或 reset 类引擎调用。
- 提交预算：一次操作最多产生一个非空 `commitText` 或一个类型化 `action`，两者互斥；ArkTS 最多执行一次编辑框写入。

所有查询使用按操作开始时捕获的启用分类不可变快照；同一次操作中不得读到一半旧分类、一半新分类。

## 2. 精确、前缀、用户规则与分页

### 2.1 路径选择表

| 输入/基础查询 | 结果 | 禁止行为 |
| --- | --- | --- |
| `rawCode == ""` | 空候选、空会话 | 枚举整个系统表或用户表 |
| 任一启用分类存在精确词条 | 只收集当前编码精确词条 | 混入更长编码 |
| 所有启用分类无精确词条、无用户精确规则，但存在更长编码 | 只收集源序第 1 项精准匹配提示 | 使用拼音、基础频率或学习分重排 |
| 无精确且无更长编码 | 空码 | 把原始字母提交到编辑框 |

多分类先按显式分类列表顺序合并；分类内部按持久化 `source_order`。相同文本的稳定去重保留排序流程中第一次出现的候选。

正式 `xiaohe-yinxing` 的提示候选可由用户主动选择，但不得参与唯一候选自动上屏、第五键顶屏、有效完整码或空码切分判定。候选栏只展示源序第 1 项及其未输入编码后缀；提示数量固定为 1，设置页不提供选项。该限制不截断精确同码候选。完整合同见 ADR 0023。

正式规则快照先按包内冻结规则、再按外部用户文件组成。同“完整编码＋词条”冲突时外部规则获胜；不同键保持两层稳定顺序。缺失或损坏外部层不得关闭包内层。完成快照组成后，候选仍只执行下表一次，不为任一来源复制算法。

### 2.2 冻结处理顺序

| 顺序 | 阶段 | 输出约束 |
| --- | --- | --- |
| 1 | 捕获启用分类快照 | 操作内不可变 |
| 2 | 判断系统分类精确命中 | 有精确则锁定精确路径 |
| 3 | 无精确时才查更长前缀 | 不进行“删空后再次前缀回退” |
| 4 | 分类顺序 + 分类内 `source_order` | 禁止 `ExistingRanking`/`user-model` |
| 5 | `#删` | 按完整编码＋词条精确匹配 |
| 6 | 普通用户词合并 | 精确路径沿用用户规则；提示路径只在系统源序项后补充缺失文字 |
| 7 | `#固` | 精确路径建立不可跨越保护前缀；提示路径不重排 |
| 8 | 1-based `#N` | 精确路径使用 `effective_position=max(N,fixed_count+1)`；提示路径不重排 |
| 9 | 稳定去重 | 保留第一次出现 |
| 10 | 形成完整最终列表 | 唯一性、首选和空码判断以此为准 |
| 11 | 建立 `CandidateSession` | 页码重置为 0 |
| 12 | limit 与分页 | 用户规则绝不只作用于当前页 |

如果系统精确候选被 `#删` 全部删除，不得在同一次查询中重新混入更长系统编码或精准匹配提示；精确路径保持锁定。现有 `merge_candidates_exact_or_prefix` 的“精确删空后回退用户前缀”行为不能直接作为正式码表后端编排，后端必须显式分离精确集合、提示集合与自动决策集合。

## 3. 三码长参数

### 3.1 定义与默认值

| 参数 | 触发时机 | 默认值 |
| --- | --- | --- |
| `autoCommitCodeLength` | 新键处理后，长度达到或超过阈值 | 4 |
| `emptyClearCodeLength` | 新键处理后，长度达到或超过阈值 | 4 |
| `topCommitCodeLength` | 接收新普通编码键前，旧段长度达到或超过阈值 | 4 |

合法范围统一冻结为 `1..=64`；正式运行使用表中冻结默认值。测试 fixture 或未来显式配置若缺失、非整数、越界，必须以稳定 `invalid_commit_policy` 拒绝，不得静默回退或纠正。三个触发参数相互独立，但均不得超过普通编码最大长度。

### 3.2 单键处理优先级

```text
捕获配置和分类快照
  -> 若为 GuidePrefix/GuideCode，走引导状态机并跳过普通三码长
  -> 普通旧段长度 >= topCommitCodeLength：执行顶屏前置决策
  -> 把本键恰好处理一次（正常追加或作为新段首键重放）
  -> 查询并完成用户规则、去重和完整候选列表
  -> 若达到 emptyClearCodeLength 且为空码：清空组合
  -> 否则若达到 autoCommitCodeLength 且满足唯一自动上屏条件：提交
  -> 建立/刷新候选会话并返回操作后状态
```

顶屏是接收新键前的前置规则，优先级高于新段的自动上屏。空码清屏与自动上屏的谓词互斥；表述顺序固定为空码清屏在前。若顶屏已经消耗本次提交预算，重放的新段仍查询和展示，但本次不得再次自动提交；后续按键重新获得提交预算。

### 3.3 自动上屏

只有同时满足以下条件才自动提交：

1. 普通 `rawCode` 长度达到或超过 `autoCommitCodeLength`；
2. 用户规则后的最终精确候选恰好一个；
3. 该候选未被 `#删`；
4. 不存在有效更长编码；
5. 不处于分号引导状态；
6. 本次操作提交预算尚未使用。

提交后普通组合、候选会话和页码清空。多个候选时即使 `#固/#N` 已确定首选，也不自动提交。

### 3.4 空码清屏

普通 `rawCode` 长度达到或超过 `emptyClearCodeLength`、最终精确候选为零、不存在有效更长编码且不在引导状态时，清空普通组合、候选会话和页码。清屏返回空 `commitText`，不把原始字母提交到编辑框。

### 3.4.1 空码正向/反向切分

空码清屏不是空码切分。2026-07-24 经产品授权，ADR 0018 冻结以下规则：

1. 只有非空 `NormalCode` 达到空码阈值，且完整编码无最终精确候选、无有效更长编码时才尝试切分。
2. 正向优先：从右向左选择具有最终精确候选的最长左前缀，提交其最终首选，保留右侧原始编码。
3. 正向无解才走反向：从左向右选择最终可见的最长右后缀，原样提交左侧 ASCII，保留右后缀。反向不提交后缀候选，避免文本倒序。
4. 切分点、候选和剩余段查询使用同一次操作捕获的分类/用户快照。`#删` 或分类关闭可使切分点失效。
5. 扫描上限默认 64 bytes，最多尝试 `len - 1` 个非空边界。
6. 切分成功只产生一个 `commitText`；剩余段只查询一次，本次不递归切分、不顶屏、不再次自动提交。
7. 无合法切分时执行 3.4 的安全清屏。

### 3.5 顶屏和第五键重放

旧段长度达到或超过 `topCommitCodeLength` 后再次收到普通编码键：

1. 从旧段完整最终候选列表读取首选；
2. 有首选：把首选作为本次唯一 `commitText`，清空旧段；
3. 无首选：不提交，清空不可提交的旧段；
4. 无论旧段是否有首选，都把当前新键作为下一段第一个键恰好处理一次；
5. 返回旧段提交文本（如有）和新段操作后的 `rawInput/preedit/candidates`。

“无首选时清空旧段并重新起段”是保守且可恢复的默认：它不伪造候选、不丢失当前键、不让超过顶屏长度的死组合无限增长。不得保留旧段后简单追加，也不得丢弃或重复第五键。

### 3.6 逐键状态表

| 场景 | 前置/查询结果 | 本键后的动作 | `commitText` | 操作后组合 |
| --- | --- | --- | --- | --- |
| 未达到任何后置阈值 | 任意可继续状态 | 仅刷新 | 空 | 保留 |
| 达到自动阈值，唯一最终精确，无更长码 | 非引导、提交预算可用 | 自动上屏 | 唯一候选 | 清空 |
| 达到自动阈值，多个最终精确 | 有首选但不唯一 | 不自动提交 | 空 | 保留全部候选 |
| 达到阈值，无精确但有有效更长码 | 前缀可继续 | 不清屏、不自动提交 | 空 | 音形显示有界提示，其他策略按各自合同保留前缀候选 |
| 达到空码阈值，无精确且无更长码 | 空码 | 清屏 | 空 | 清空 |
| `#删` 使最终精确变为零 | 精确路径已经锁定 | 不二次前缀回退；按有无有效更长码及空码阈值处理 | 空 | 保留可继续状态或清空 |
| `#固/#N` 只改变首选 | 候选数量不变 | 唯一性仍由数量决定；顶屏提交新首选 | 依触发类型 | 依触发类型 |
| 分类快照改变唯一性 | 变化前先 reset | 用新快照重算，不沿用旧会话 | 空 | 新输入从空态开始 |
| 旧段达到顶屏长度，再输入第五键 | 旧段有首选 | 提交旧首选，重放第五键 | 旧首选 | 第五键成为新段首键 |
| 旧段达到顶屏长度但无首选 | 不可提交 | 清旧段，重放当前键 | 空 | 当前键成为新段首键 |
| 连续顶屏 | 每个旧段均有首选 | 每次触发操作最多提交一个旧段 | 每次最多一个 | 每次保留新段首键 |
| 顶屏后退格 | 上次提交已进入编辑框，新段非空 | 只删除新段一个编码 | 空 | 新段缩短/为空，已提交文本不回滚 |
| 参数不相等 | 见 3.2 | 先旧段 top；后置 empty；否则 auto | 最多一个 | 确定性结果 |

示例（默认均为 4）：`abcd` 有多个候选时不自动上屏；随后输入 `e`，先提交 `abcd` 首选，再返回 `rawInput="e"`。若 `abcd` 没有首选，输入 `e` 不提交任何内容，但仍返回 `rawInput="e"`。

## 4. 分号引导状态机

### 4.1 状态图

```text
Idle --普通字母--> NormalCode --退格至空--> Idle
  |                    |
  +--分号------------> GuidePrefix
                         |
                         +--字母--> GuideCode --继续字母--> GuideCode
                         |             |
                         |             +--退格删至空--> GuidePrefix
                         +--退格-----------------------> Idle

GuidePrefix / GuideCode --方案切换、会话结束、编辑框切换、异常 reset--> Idle
```

分号仅在“码表方案 + 中文键盘模式”中作为引导键。`xiaohe`、英文、数字和普通符号模式继续走当前分号行为，不调用码表引导状态机。

`GuidePrefix` 表示只输入了分号；`GuideCode` 表示至少一个引导字母。引导编码为空时不枚举整张引导表，只精确查询快符保留码 `_` 并显示其候选。引导状态只查询专用引导表，不查询普通分类表；普通分类候选也不得混入。引导默认不触发普通自动上屏、空码清屏或顶屏。

### 4.2 引导事件表

| 当前状态/事件 | 冻结行为 | 下一状态 |
| --- | --- | --- |
| Idle 按分号 | 消费为引导前缀；显示快符 `_` 默认候选 | GuidePrefix |
| NormalCode 按分号 | 不猜测或提交普通码首选；无提交清空普通组合，再进入引导前缀 | GuidePrefix |
| GuidePrefix 输入一个字母 | 查询专用引导表的精确/更长前缀 | GuideCode |
| GuideCode 连续输入字母 | 追加并重新查询专用引导表 | GuideCode |
| GuidePrefix 按退格 | 删除分号引导，不影响编辑框 | Idle |
| GuideCode 连续退格 | 先逐字删除；删完字母后停在 GuidePrefix；再退格退出 | GuideCode / GuidePrefix / Idle |
| GuidePrefix 再按分号 | 若快符表存在 `;` 保留码则直接提交该项（模板默认 `；`） | Idle |
| GuideCode 再按分号 | 清空现有引导字母并重新开始 GuidePrefix，显示 `_` 默认候选 | GuidePrefix |
| 引导状态输入非法键/普通符号 | 取消引导且不提交引导候选；该键按原键盘模式规则只路由一次 | Idle 或外层模式状态 |
| 引导状态按空格且有首选 | 提交首选，消费空格，不追加字面空格 | Idle |
| 引导状态按空格且无首选 | 退出引导并按外层规则提交一个空格 | Idle |
| 引导状态按回车且有首选 | 提交首选，消费本次回车，避免双动作 | Idle |
| 引导状态按回车且无首选 | 退出引导并转发一次既有回车动作 | Idle |
| 引导状态选择候选 | 提交所选候选并清空引导会话 | Idle |
| 引导状态切换方案/模式 | 无提交 reset，不把引导内容带入新方案 | Idle |
| 引导表无候选 | 保持可编辑引导码；允许继续输入或退格；不自动清屏 | GuideCode |

普通编码中按分号、连续分号、非法键、空格和回车规则是缺少正式提供方规则时的保守默认，必须列入来源确认清单。引导表是否允许用户 `#删/#固/#N`、是否使用与普通表相同的 ExactOrPrefix，也保持“未确认”；在书面规则到达前，测试 fixture 只验证本表的状态退出和专用表隔离，不声称是官方规则。

## 5. reset 事件矩阵

“清”表示必须清空；“保留”指逻辑配置/最后有效快照继续存在，不表示跨句柄复用旧内存对象。所有 reset 默认禁止提交当前组合。

| 事件 | 原始编码 | 引导状态 | 候选会话/页码 | 查询缓存 | 用户词库快照 | 用户设置 | 提交当前组合 | 回退 `xiaohe` |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `xiaohe` -> 码表 | 清 | 清 | 清 | 清 | 保留/按配置加载 | 保留 | 否 | 仅码表创建失败时 |
| 码表 -> `xiaohe` | 清 | 清 | 清 | 清 | 保留 | 保留 | 否 | 已切入 `xiaohe` |
| 输入会话结束 | 清 | 清 | 清 | 清 | 保留 | 保留 | 否 | 否 |
| 新输入会话开始 | 清 | 清 | 清 | 清 | 保留/校验 | 保留 | 否 | 仅后端不可用时 |
| 编辑框切换 | 清 | 清 | 清 | 清 | 保留 | 保留 | 否 | 否 |
| 前台应用切换 | 清 | 清 | 清 | 清 | 保留 | 保留 | 否 | 否 |
| 键盘隐藏 | 清 | 清 | 清 | 清 | 保留 | 保留 | 否 | 否 |
| ExtensionAbility 销毁 | 清并销毁 | 清 | 清 | 清 | 磁盘数据保留 | Preferences 保留 | 否 | 下次创建时判定 |
| Native 句柄重建 | 清 | 清 | 清 | 清 | 从最后有效文件重载 | 保留 | 否 | 码表重建失败时 |
| 码表资源损坏/校验失败 | 清 | 清 | 清 | 清 | 保留 | 保留并记录不可用状态 | 否 | 是 |
| 分类快照替换成功 | 清 | 清 | 清 | 清 | 保留 | 保存新开关 | 否 | 否 |

| 三码长参数变化 | 清 | 清 | 清 | 清 | 保留 | 保存已校验参数 | 否 | 否 |
| 引擎异常恢复 | 清 | 清 | 清 | 清 | 重载最后有效快照 | 保留 | 否 | 码表恢复失败时 |

禁止旧方案的原始编码、引导状态、候选、页码或查询缓存进入新方案。用户主动“候选提交后切换模式”属于切换前独立提交操作，不属于 reset 自身；reset 本身永不隐式提交。

## 6. `CompositionResult` 协议评估

### 6.1 代码证据

- Rust `CompositionResult` 同时包含 `commit_text`、`raw_input`、`preedit_text`、候选和 `composition_finished`。
- `ImeEngine::select_candidate` 的阶段 8 部分提交先移除已消费编码，重新解析剩余编码，再把 `commit_text` 放入同一个结果并保持 `composition_finished=false`。
- C ABI 返回 UTF-8 JSON buffer；函数签名不依赖 JSON 字段布局。
- C++ `ParseCompositionResult` 和 Node-API 转换器继续转发现有 `commitText/rawInput/candidates/action` 字段，不增加提交策略。
- ArkTS 类型和 `NativeEngineGateway` 继续严格校验 ABI 4 的既有必填字段。
- `InputSessionController.insertLetter` 已先执行 `processKey` 的非空 `commitText` 一次；成功后再保存同一结果的新段 `rawInput/candidates`，纯自动提交不会建立空预览，提交失败执行受控 reset。

### 6.2 结论与后续不变量

顶屏结果本身无需继续升级 `CompositionResult`。当前 interface/ABI version 已在阶段 11.6.6 升级为 4；11.6.7 不增加 C ABI 函数或字段，顶屏结果仍使用：

```text
commitText = 旧段首选
rawInput = 已重放的新段原始编码
preeditText / candidates / page = 新段状态
compositionFinished = false
```

当前 ArkTS 接入满足：先对非空 `commitText` 执行且只执行一次 IME Kit 提交，再按同一结果刷新预览和 store；不因提交而丢弃非空 `rawInput`。若编辑框提交失败，不假装已同步，而是进入受控 reset/错误恢复。C++ 只转换字段，不理解提交原因。

不新增 `commitReason`、`clearReason`、`remainingRawInput` 或 `backendId`。如果后续自动化证明无法仅由现有输出区分必须执行的动作，先更新 `API_CONTRACT.md` 并同步四层兼容测试，再实现业务；不得单层扩展。
