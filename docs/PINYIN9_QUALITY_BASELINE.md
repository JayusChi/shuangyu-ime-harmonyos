## 结论

本基线测量的是当前正式 `ImeEngine`、`schemeId=pinyin-9` 和应用安装位置的正式 `production.lex`。评测逐位调用正式按键接口，只在数据声明的位置调用正式 `insert_segment_boundary`，不选择正确拼音路径，不重排、补充或过滤候选，遍历正式候选分页到末页，并在每条样本后完整 reset。用户学习和 session 学习均关闭，没有设置、读取或写入真实用户模型路径。

唯一一次 blind 命令内部完成三轮后，465 条九键专项 blind 样本的结果是：Top1 `8.602%`、Top3 `12.688%`、Top5 `13.548%`、MRR `0.109757`、目标完全未召回率 `78.710%`。正确 canonical 拼音路径在 32 路上限被裁剪的比例为 `60.000%`；正确路径存在但目标汉字未召回为 `9.247%`；目标候选已召回但不是首选为 `12.688%`。

这些结果很低，且长句、高重码、错误输入和性能均存在严重问题。本阶段没有设置任意“通过线”，也不宣布 PASS。项目没有商业输入法在同一冻结数据集上的结果，因此不得据此声称达到、接近或超过商业输入法。

## 数据来源、分层与冻结身份

数据来源和生成方法见 `artifacts/pinyin9-evaluation/dataset/sources.json` 与 `DATASET_PROVENANCE.md`：

- 公开回归层共 900 条，来自字节冻结的全拼 v1 数据中六个 clean 类别。工具按标准字母到 2～9 的映射转换，保留原 expectedTexts、类别、来源和 `sourceSampleIds`，标记为 `converted_public_regression`。它不是新 blind 数据。
- 九键专项层共 620 条，其中 dev 155、blind 465。20 个类别均严格按 25%/75% 划分。32 条常用单字为项目独立编写；其余为基于准确标识的项目冻结样本所做的确定性词素组合、简拼、未完成尾音、显式分音、一次漏按/多按/邻键/错序和模糊音变换。
- expectedTexts 没有从当前引擎候选反向生成。数据不含商业输入法候选、用户数据、网页抓取或许可不明语料。

## 已覆盖与未覆盖

已覆盖：常用单字、二至四字词、现代聊天、长句连续输入、切分歧义、人名/地名/机构/品牌专业词、多音同音、高数字重码、多合法路径、简拼、未完成尾音、显式分音、一次漏按/多按/邻键/错序、模糊音/方言式变换；正式按键、分音、分页、reset、路径公开状态、用户学习关闭、确定性和主机性能均被实际执行。

## 下一阶段优先技术点

1. 优先改进 T9 路径搜索与排序/裁剪，使 canonical 路径在高重码和长串下能进入 32 路；blind 有 60.000% 在候选查询前已丢失正确路径，是最大单一瓶颈。
2. 在路径存在时改进词库/整句召回与多音词覆盖，并单独诊断组合词的解码边界；blind 有 9.247% 属于路径存在但目标未召回，polyphone_homophone 最突出。
3. 降低多路径候选生成和整句解码成本，并明确处理超过 64 位输入；blind 每键 P95 634.066 ms、长串 P95 785.825 ms，15 条样本每轮发生状态丢失。排序优化应在上述两项之后验证，当前另有 12.688% 的已召回目标首选错误。

以上仅为下一阶段建议。本阶段没有修改 T9 解析、路径排序/裁剪、候选召回/排序、整句解码、用户学习、词库、上下文模型或既有全拼/双拼/音形行为。
