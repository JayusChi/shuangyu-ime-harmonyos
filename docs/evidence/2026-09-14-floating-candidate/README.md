# 浮动候选尺寸稳定与阴影

日期：2026-09-14。结论：744 项 ArkTS 回归通过；手机模拟器的虚拟键盘、实体键盘模式及深色外观通过；正式 release 签名 HAP 构建和资源门禁通过。

## 反馈与原因

输入依据为客户 `录1.mp4` 和白色圆角候选卡片参考图。录屏约 4 秒处，从 `k` 更新到 `kn` 时，文字已替换但窗口短暂保持原宽度，右侧候选被截断并出现水平滚动条。抽样帧中的卡片高度均约 122 像素，未把客户描述的高度变化当作已经量测复现的事实。

原来 ArkUI 页面直接订阅输入状态，系统面板则异步调整尺寸；两个更新过程不同步，连续事件还会重复排队调整窗口。

## 修改

- 增加独立展示快照：系统窗口完成 resize/move 后才发布对应的候选和设置；连续更新仅处理最新版本，异步旧结果不再重新显示。
- 同一可见组合内宽度只随内容增长，退格、短候选和字体测量就绪不再把窗口挤窄；结束组合后重新从紧凑宽度开始。展开/收起、候选数量、方案、字号和屏幕变化会重新计算布局。
- 单行高度按照字号、固定行高和选中项留白计算。取消水平滚动条，保留横向滚动和展开能力。
- 点击候选前核对会话代数、原始编码、页码和候选内容，避免调整尺寸期间点击旧候选误提交新候选。
- 浅色浮窗使用白色卡片、细灰边框、浅灰选中背景和较小的灰色序号；深色使用独立深灰配色。圆角 16 vp，阴影半径 16 vp、向下偏移 6 vp，四周预留 24 vp。按本机 SDK `component/common.d.ts` 的 ShadowOptions 定义，将阴影参数从 vp 转为 px。

## 验证

ArkTS 全量 **744/744 PASS**，新增 7 项，覆盖两种键盘的延迟 resize、快速输入合并、行高稳定、回删不收窄、清空/下一组合、字号更新、过期候选点击，以及阴影空间和浅深色配色。既有展开/收起、回车编码、方括号翻页和候选回删测试一并通过。

手机模拟器 `127.0.0.1:5555`，1320×2856，density=3.5；正式页面的开发签名 Release 构建安全覆盖安装。分别用虚拟按键和系统注入的硬件 keyEvent 验证 `k → kn → 回删到 k → 点击“可”`。两种模式下量测一致：

| 输入阶段 | 白色卡片宽×高 / px | 含透明阴影区域的系统窗口 / px |
| --- | --- | --- |
| k | 718×196 | 886×364 |
| kn | 812×196 | 980×364 |
| 回删到 k | 812×196 | 980×364 |

两项候选的布局边界始终位于卡片内，上屏文本为“可”，上屏后候选窗隐藏。另验证硬件 Enter 上屏 `kn` 和深色浮动候选；最终截图人工检查通过。测试前后 **47 项持久化设置完全一致**，恢复了虚拟键盘、固定候选栏与跟随系统主题。
