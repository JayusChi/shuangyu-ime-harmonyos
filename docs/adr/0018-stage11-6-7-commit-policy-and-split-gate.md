# ADR 0018：阶段 11.6.7 四码提交策略与空码切分门禁

状态：接受（2026-07-23 部分实施；2026-07-24 经产品授权冻结切分补充合同）。

## 背景

阶段 11.6.1 已在 `CODE_TABLE_BEHAVIOR_SPEC.md` 冻结三项普通码表行为：

- 四码最终精确候选唯一且无有效更长编码时自动提交；
- 旧段达到四码后，新普通键到来前顶屏旧首选，并把新键作为新段首键处理一次；
- 四码构成空码时清空组合，不产生提交。

同一合同也明确了候选、用户规则、分类快照、分页、Guide 隔离和单次提交预算。上述行为只依赖普通码表数据、分类快照、用户规则快照、`NormalCode` 和 ABI 4 已有的 `commitText + rawInput`，不依赖仍延期的快符、正式引导、日期时间或成对符号数据。

但是，仓库没有冻结空码正向/反向切分的扫描顺序、候选切分点优先级、提交段、剩余段或多解裁决规则。原始 Android 配置被明确隔离且不得作为 HarmonyOS 行为来源。

## 决策

1. 在现有 Rust `CodeTableStateMachine` 中加入不可变 `CodeTableCommitPolicy`，集中保存：
   - `auto_commit_length = 4`
   - `top_screen_length = 4`
   - `empty_code_clear_length = 4`
   - `normal_code_max_length = 64`
2. 所有字段必须在 `1..=64` 内，且三个触发长度不得超过普通编码上限。非法 fixture/构造参数返回稳定 `invalid_commit_policy`，不静默修正。
3. 每次普通按键操作只捕获一次分类和用户规则快照。旧段顶屏、新段查询、最终精确候选、有效更长编码、空码清屏和自动提交共用这组快照。
4. 唯一性使用用户规则和稳定去重后的完整最终精确候选，在 UI limit 和分页之前判断。
5. 有效更长编码必须在相同快照下具有至少一个最终可见精确候选；被 `#删` 后不可见的更长记录不再阻止自动提交。
6. 第五码先取得旧段完整最终首选并占用本次提交预算，再清旧段并处理新键一次。新段即使满足提交条件，本次也不得产生第二个提交。
7. ABI/interface 保持 4。Rust 返回旧段 `commitText` 与新段 `rawInput/candidates`；C++ 只桥接；ArkTS 只执行一次提交并保存同一结果中的新段。
8. 空码切分只在非空普通编码达到空码阈值、完整编码无最终精确候选且无有效更长编码时运行；空字符串、Guide 和已经产生提交的操作不进入切分。
9. 正向切分从右向左扫描非空边界，选择具有最终精确候选的最长左前缀，提交该前缀的最终首选，右侧原始编码作为剩余段。
10. 若正向无解，反向切分从左向右扫描，选择具有最终可见精确候选或有效更长编码的最长右后缀；为保持编辑器文本顺序，左侧无法解释的 ASCII 原样作为唯一 `commitText`，右后缀作为剩余段。反向切分不提交后缀候选，避免产生“后段在前、前段在后”的倒序文本。
11. 正向优先于反向；多个正向点取最长左前缀，多个反向点取最长右后缀。相同输入和快照的结果唯一。
12. 切分扫描上限默认为 64 bytes，最多尝试 `len - 1` 个边界；边界只落在 ASCII 码字节之间。切分上限必须在空码阈值和普通编码上限之间，非法策略返回 `invalid_commit_policy`。
13. 切分成功后只产生一个提交，剩余段只赋值和查询一次；同一操作不再对剩余段执行自动提交、顶屏或递归空码切分。后续显式按键重新获得提交预算。
14. 切分点、提交候选和剩余段查询共用操作开始时捕获的分类与用户规则快照。分类关闭或用户删除可使切分点失效。
15. 无合法正向或反向切分时执行既有安全清屏，不产生提交。

## 2026-07-24 授权与取舍

产品授权由项目负责人在当前实施会话中明确给出：“授权你制定规则并实现”。本 ADR 据此冻结上述项目规则，不使用原始 Android 配置作为行为来源。

反向路径选择“提交原样左段、保留合法右段”，是为了同时满足：

- 不倒置用户输入的文本顺序；
- 不把右侧候选提前插入到左侧输入之前；
- 不丢弃无法解释的左侧字符；
- 继续复用 ABI 4 的 `commitText + rawInput`；
- 每次操作仍只有一个编辑器提交。

若未来产品要求丢弃左段、倒序提交或其他行为，必须新增 ADR 并提供迁移与兼容测试，不得静默改变本合同。

## 后果

- `xiaohe` 双拼解析、排序和用户学习不变。
- `GuidePrefix/GuideCode` 跳过普通四码策略。
- 分类更新只重算，不在设置操作中提交；新的唯一性由后续显式按键触发。
- Release 默认方案、正式设置入口和资源边界不变；不提前实现 11.6.8。
