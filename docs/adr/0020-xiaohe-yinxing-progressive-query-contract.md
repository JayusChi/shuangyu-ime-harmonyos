# ADR 0020：小鹤音形渐进查询合同与阶段 0 基线

- 状态：Accepted
- 日期：2026-07-27
- 决策范围：后续“小鹤音形改进”阶段
- 阶段 0 实现状态：合同与旧行为已冻结
- 阶段 1 实现状态：已实现并通过主机与 x86_64 模拟器运行时页验收

## 背景

当前 `code-table-runtime::query_exact_or_prefix` 是所有码表后端共享的既有语义：

1. 当前编码存在精确候选时，只返回精确候选。
2. 当前编码不存在精确候选时，才返回更长编码的前缀候选。

该合同对现有 fixture 已形成兼容性约束。对于小鹤音形，二码存在精确简码时会隐藏相同音节下的三码、四码候选；阶段 0 冻结了旧事实、目标合同和隔离边界，阶段 1 在不改变通用查询函数的前提下为正式方案实现一至三码渐进候选。

## 决策范围

后续渐进查询只允许影响方案：

```text
xiaohe-yinxing
```

不得改变：

```text
xiaohe
```

也不得隐式改变通用码表 fixture、导入/转换工具、用户词库工具、其他方案或通用 `query_exact_or_prefix` 的既有语义。

## 架构决策

不直接修改 `query_exact_or_prefix`。阶段 1 在调用边界增加了显式查询策略：

```rust
enum CodeTableQueryStrategy {
    ExactOnly,
    ExactOrPrefixFallback,
    ProgressiveXiaoheYinxing,
}
```

策略由 `ime-engine` 的正式方案注册边界按 `scheme_id` 显式选择，不能靠输入长度、bundle 文件名或全局开关猜测。`query_exact_or_prefix` 和默认状态机构造器继续选择 `ExactOrPrefixFallback`；正式 `xiaohe-yinxing` 选择 `ProgressiveXiaoheYinxing`。

## 阶段 1 实现记录

- `query_with_strategy(_and_snapshot)` 在查询层按策略构造候选来源；渐进策略先遍历完整精确阶段，再遍历编码长度严格更长的前缀阶段，并按文字保留第一次出现的完整候选记录。
- `CodeTableStateMachine` 保存显式策略。同一次按键只捕获一份分类和用户词库快照；展示查询、精确候选、有效后续和自动提交均复用该操作快照。
- 用户词库新增渐进前缀规则视图；`#固/#删/#N` 继续按完整 `(code,text)` 键处理，在分页前完成并稳定去重。
- 正式方案候选快照上限为 512；系统候选源读取额外预留当前用户规则数量并硬限制为 4,096，以便删除后回填且禁止无界返回，再在规则与去重后截断。ArkTS/C++/FFI 协议未变化，候选栏只呈现当前页。
- 四码渐进分支显式退化为 `ExactOnly`；自动提交仍调用独立精确候选和有效后续判断，不读取展示列表长度。
- 正式 bundle schema、字节、SHA-256 和八分类源数据均未修改。

## 一至四码目标合同

### 一码

- 精确一简候选优先。
- 以当前一码开头的更长候选作为补充。
- 按候选文字稳定去重。

### 二码

- 精确二简候选优先。
- 同时展示当前音节下的三码、四码候选。

### 三码

- 精确三码候选优先。
- 同时展示匹配前三码的四码候选。

### 四码

- 只返回完整四码精确候选，不混入其他路径。
- 过滤及用户规则处理后的完整候选唯一，且不存在有效后续码时，允许自动提交。

以上是后续阶段目标，不是阶段 0 的运行时行为。

## 排序、去重与分页合同

后续目标排序层：

1. 用户固顶。
2. 当前输入的精确简码候选。
3. 系统更长编码候选。
4. 用户指定位置。
5. 分类顺序。
6. 分类内 `source_order`。

最终实现仍须服从现有用户规则的冲突与保护合同。所有用户规则必须在分页前应用；跨分类按候选文字稳定去重；完整合并后再分页。分类过滤、完整候选列表、唯一性、有效后续判断和自动提交必须读取同一份不可变的分类与用户规则快照，禁止同一次按键中分阶段重读可变状态。

## 自动上屏与切分合同

- 一至三码的渐进候选不得触发四码唯一自动提交。
- 四码唯一性基于分类过滤后、用户规则处理后、语义正确的完整四码精确候选集合。
- 第五键顶屏只能提交上一段的正确首选，并将当前键恰好重放一次。
- 不得重复提交。
- 空码正向/反向切分不能把前缀候选误认为可提交的完整编码段。
- 分类开关或用户删除改变唯一性时，自动提交必须基于更新后的同一不可变快照重新计算。

## 小鹤双拼隔离

`xiaohe` 继续使用 `ShuangpinParser::xiaohe`、正式双拼词典、句子解码和其现有用户模型。小鹤音形分类、内置规则、外部用户规则和后续渐进策略不得进入双拼后端。方案切换必须清空上一后端的组合、分页和缓存状态；切回双拼后按其原合同重建会话。

## 离线、安全与权限

首个改进版本继续完全离线：

- 不新增网络权限或账号权限。
- 不上传用户输入。
- 不执行来源配置中的脚本、命令、URL、FTP、WebDAV、动态路径或外部程序。
- 原始 `txt/ini`、审计资料、trace 和敏感配置不得进入 Release HAP。
- 后续静态扩展资源必须使用独立审计、固定哈希和显式白名单协议。

## 兼容性

阶段 0 明确保持不变：

- 正式 bundle 格式 `HSPYXP01 1.0`。
- 正式源数据和 `xiaohe-yinxing-production.hsyx` 字节。
- 用户词库文本格式及 `#删`、`#固`、`#N` 语义。
- 小鹤双拼查询合同。
- 分页大小和分页语义。
- 四码自动提交、第五键顶屏和空码切分语义。
- 已安装资源的大小/SHA-256 校验、兼容性拒绝和损坏回退合同。
- 应用权限集合。
