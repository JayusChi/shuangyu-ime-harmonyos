# ADR 0022：小鹤音形精准匹配合同与渐进基线

- 状态：Accepted
- 日期：2026-08-04
- 决策范围：`xiaohe-yinxing` 精准匹配改造
- 阶段 0 状态：已完成
- 替代关系：替代 ADR 0020 的“渐进候选作为后续产品目标”；ADR 0020 继续作为既有实现和历史证据保留

## 背景

ADR 0020 为正式 `xiaohe-yinxing` 引入 `ProgressiveXiaoheYinxing`：一至三码合并精确简码与严格更长的前缀候选，正式快照最多 512 项。该实现解决了二码候选偏少，但产品体验逐渐接近从大候选集中选字。

当前产品方向改为编码消歧优先：前两码确定读音，后两码确定字形；完整四码只处理真实精确结果，唯一时自动提交，重码时只保留完整码重码。候选数量不再是音形质量指标。

## 决策

接受《精准匹配修改.md》第 3～6 节为后续实现合同：

1. 一至三码不得因为候选唯一而自动提交，只提供当前完整简码及严格受限的反馈。
2. 普通音形查询不再把大规模前缀项作为可提交候选或可展开候选返回。
3. 四码只查询完整编码；分类、用户硬规则和稳定去重完成后，唯一结果自动提交一次，多个结果保持组合并只显示真实重码。
4. 无合法完整结果时不得提交前三码预览首选；继续服从既有可恢复空码与切分合同。
5. 第五码顶屏只能提交上一段合法首选，并把当前键作为下一段第一码恰好重放一次。
6. 简码与正式词组继续存在，但只按当前完整编码精确命中，并由用户主动提交一至三码简码。
7. `xiaohe` 小鹤双拼的查询、排序、学习、句子、分页和候选展开全部隔离。

完整码重码的稳定顺序继续是用户显式固顶/位置、分类优先级、分类内 `source_order` 和稳定 ID；自动学习不得改变完整码重码顺序。`#删` 可以改变过滤后的唯一性，`#固/#N` 只改变合法候选顺序。

第二候选快捷键仍待单独产品确认；这不改变完整码查询、唯一性或阶段 0 基线合同。

## 阶段 0 决策边界

阶段 0 只增加诊断示例、生成器、机器快照、ADR、测试和报告，不修改：

- `query.rs`、`state.rs` 或 `formal.rs` 的生产查询与状态机行为；
- FFI、C++、ArkTS 协议和候选 UI；
- 正式 bundle、manifest、分类记录、用户词库格式或源数据；
- `xiaohe` 小鹤双拼运行时；
- 应用权限。

## 冻结证据

当前渐进基线位于：

```text
dictionaries/audit/xiaohe-yinxing/precise-match-stage0/
```

统一入口：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\generate-xiaohe-yinxing-precise-match-stage0.ps1
```

候选和双拼快照各运行两次并逐字节比较。主机性能单独采样，不作为易波动的单元测试阈值。历史渐进改造前基线 `dictionaries/audit/xiaohe-yinxing/baseline/` 保留且不覆盖。

## 隔离与兼容

- 精准策略只能由正式 `scheme_id='xiaohe-yinxing'` 显式选择。
- 通用 `query_exact_or_prefix` 和 `code-table-fixture` 不得隐式改变。
- `xiaohe` 继续走双拼 parser、正式双拼词典、句子解码、排序和用户模型。
- 方案切换清空组合、页码和候选；切回方案后从空状态重建。
- 首版优先保持现有协议字段、bundle schema 和用户词库格式不变。

## 后果

阶段 1 将新增或启用音形专用精准策略，并把历史渐进策略保留为内部对比和至少一个正式版本周期的回滚路径。精准实现必须以本 ADR 和《精准匹配修改.md》为新期望，以本阶段机器快照为预期变化对比；不得自动覆盖快照来掩盖回归。
