# ADR 0025：T9 数字 Trie、Rust 消歧状态与组合选择 ABI

- 状态：Accepted
- 日期：2026-08-12

## 背景

传统 9 键的一个数字对应 3 或 4 个字母。逐位展开全部字母串会产生 `3^n`/`4^n` 复杂度，而且把合法音节判断、分词、候选排序或当前选择下放到 ArkTS/C++ 会形成多套不一致状态。

阶段 3 还需要在同一数字串的多个合法拼音之间显式切换，并在切换后立即刷新候选。阶段 1 已冻结 `CompositionResult.currentPinyin` 与 `pinyinCombinations`，但还没有跨层选择操作。

## 决策

1. Rust 初始化时把唯一合法拼音音节集合转换为数字签名并建立数字 Trie；运行时只沿数字 Trie 查询，不生成任意字母排列，也不扫描完整音节集合。
2. 拼音切分、显式边界、当前选择、删除恢复和稳定路径顺序全部归 `T9PinyinParser` 所有。`rawInput` 只保存 `2`～`9`，边界单独保存。
3. 动态规划必须使用集中硬上限：64 位输入、6 位单音节深度、每偏移 32 路、每起点 512 个生成状态、最多 32 个展示组合和 65 个前缀缓存槽。
4. 初始歧义候选在 Rust 内聚合有界拼音路径，并复用正式查询、整句、排名、分页和用户模型；显式选择后清除候选会话，只按所选路径重查。
5. 新增 `ime_engine_select_pinyin_combination(handle, index, out_buffer)`，并同步 Node-API、ArkTS gateway 与 coordinator。索引 0 指 `currentPinyin`，后续索引依次指 `pinyinCombinations`。
6. interface/ABI 同步升级为 7，engine version 为 `0.0.1-pinyin-stage3`。
7. 用户学习键继续使用最终候选稳定 ID，并把 `pinyin-9` 作为独立 `scheme_id`；临时展开路径不进入用户模型。
8. C++ 只做参数校验、UTF-8/JSON 转换和转发；ArkTS 只发数字/选择操作并保存结果。本 ADR 不启用阶段 4 UI。

## 结果

优点：

- 复杂度由合法音节 Trie 和显式上限约束，不依赖每个数字对应的字母数做指数增长。
- Rust 是路径、候选和学习的唯一真实来源；跨语言层不重复实现 T9。
- 组合选择复用现有结果结构，ABI 变化小且可以独立测试。
- 现有双拼、全拼、音形的解析和候选链不需要复制。

代价：

- 最坏 64 位高碰撞输入仍会进行逐键有界重算；需保留 Release P50/P95 基线，后续只能在不改变稳定顺序和上限语义的前提下优化增量缓存。
- interface/ABI 6 客户端不能连接 ABI 7 引擎，所有声明与静态库必须同时升级。
- `pinyin-9` 引擎可用但档案仍禁用；正式产品可见能力必须等待阶段 4。

## 未采用方案

- 全字母组合展开：指数复杂度，拒绝。
- 每次输入扫描全部合法音节：热路径与音节集合大小绑定，拒绝。
- ArkTS/C++ 本地切分或排序：破坏单一真实来源，拒绝。
- 用候选选择接口隐式代表拼音路径选择：候选可能跨路径合并，无法表达稳定的显式消歧，拒绝。
- 把所选字母串写回 raw input：破坏数字删除、边界和阶段 4 九宫格显示语义，拒绝。
